# HTML UI/UX 採点レビュアー

HTMLファイル（特に単一ファイルの静的レポート・予想表・ダッシュボード）を、UI（見た目・レイアウト）とUX（体験・情報設計）の2軸で採点し、改善提案までを一貫して行うスキル。

## いつ使うか
- 「このHTMLをUI/UXの観点で採点して」「レビューして」と依頼されたとき
- 生成物HTMLの品質評価、改善点の洗い出しを求められたとき
- 採点後に「反映して」と言われたら、既存構造を壊さず追記方式で改善を実装するところまで担う

## 進め方（必ずこの順序）

### 1. 読み込みと把握
- ファイルが大きい（数百KB／数千行）ことが多い。`read_file` は先頭の `<head>`/CSS と主要構造だけ読み、本文データは `grep` で構造タグ（`<body>` `<section>` `<table>` `<script>` `role=` `aria-` `scope=` `<button>` など）を拾って全体像を掴む。全文読みは避ける。
- `show_html` → `save_screenshot`（`save_path` 必須）で実レンダリングを確認。重いページは描画タイムアウトするので、開いてから `sleep` を挟む。
- ライト/ダーク両対応なら両方、モバイル幅（`eval_js` で `document.documentElement.style` やメディアクエリ）も確認。

### 2. 採点（100点満点 = UI 50 + UX 50）
必ず総合スコアと英字グレード（A/B/C…）を出し、UI・UX別に配点を明示する。各軸「良い点」と「減点」を箇条書きで、具体的なセレクタ・数値・行番号を根拠として添える。

**UI（50点）チェック観点**
- デザイントークン設計の一貫性（`--*` 変数、配色ペアのコントラスト＝WCAG AA）
- ドメイン準拠の配色・記号（例：競馬の枠番色、馬場種別バッジ）
- 数値表示（`tabular-nums`、桁揃え、`table-layout:fixed`、横スクロール対策）
- レイアウト崩れ対策（`overflow-wrap:anywhere`、`min-width:0`、`grid-template-areas` によるモバイル再配置）
- 開閉インジケータ、sticky＋`scroll-margin-top` の着地補正、`:focus-visible`
- DOM規模・描画負荷（巨大な一括展開は減点。`content-visibility` の有無）
- 極小フォント（実用下限 ~12px）、コントラスト不足

**UX（50点）チェック観点**
- 情報アーキテクチャ：結論ファースト（「最初に見るポイント」等）、段階的開示、ドリルダウン導線
- 信頼性・誠実さ：未校正/後付けの区分明示、少サンプル注記、上限・リスク警告、フィルタ条件の明示
- アクセシビリティ実装（宣言だけで未実装になっていないか厳しく見る）：`role`/`aria-*`/`<th scope>`、`title` 依存でタッチ/SRに根拠が届かない問題
- 操作系：絞り込み・検索・「先頭へ戻る」、長大リストのスキャン性
- データの視覚エンコード（スコアのバー/ヒート化）
- 専門用語・略語の凡例/用語集の有無

### 3. 改善提案
優先度順に上位5件程度。「大きく効く2〜3点」を明示する。既に高品質な部分（配色・トークン等）は「作り直し不要」と伝え、無駄な変更を勧めない。

### 4. 反映（依頼された場合のみ）
**鉄則：既存の8千行規模のデータ構造・見た目は一切変えない。追記方式で実装する。**
- CSSは最後の `</style>` 直前、JSは `</body>`/`</main>` 直前に `run_script` で挿入する。`str_replace_edit` は空白差異で失敗しやすいので、大きな挿入は `run_script` を使う。
- 機械的な一括付与（`<th scope="col">`、`aria-label` 展開など）は `run_script` の正規表現置換でまとめて行い、件数をログ出力して検証する。
- 実装後は `show_html`＋`sleep`＋`eval_js` で、要素数・フィルタ動作・カウント表示を実際にクリックして検証する。
- 追加要素には接頭辞（例 `.ux-`）を付け、`@media print` で操作系を隠す。

## よく効く定番の改善パッチ
1. `<th scope="col">` の一括付与（低コスト・確実）
2. `title` 依存の根拠を `aria-label` にも展開（タッチ/SR対応）
3. 主要リスト領域を `role="region" aria-label` 化
4. `content-visibility:auto; contain-intrinsic-size` で描画負荷軽減
5. sticky 絞り込みツールバー（場/カテゴリチップ＋「◯◯のみ」トグル＋表示件数カウント、`aria-pressed` 連動）
6. 「先頭へ戻る」FAB（スクロール量で表示切替）
7. 印・専門用語の凡例/用語集（`<details>` 折りたたみ）
8. スコア/確率のバー可視化（閾値で色分け）

## トーン
- 「正直にお伝えすると」で始められるような率直さ。過大評価しない。
- 前バージョンがあれば比較して向上/退行を明言する。
- ユーザー設定に従い簡潔・直接的に。冗長な説明は避ける。
