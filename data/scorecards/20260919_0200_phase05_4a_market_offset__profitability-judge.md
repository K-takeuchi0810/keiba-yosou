## 依頼 4 点への回答

### 1. 購入条件を書き忘れた件の処理は妥当か

**方向は妥当、記録が不十分**。0.5-3 で先に公表した 2 集合を使う判断は選択自由度を殺しており、閾値探索もしていない。しかし事前登録の効力は「後から改変できない証跡」にある。より誠実な代替:
- 実行前に PREREG へ日付つき追記を **単独 commit** し、そのあと run する
- 試験対象 = `edge > 5pt`、対照 = 全頭 (合否を決めない) と峻別
- 最小 n を書く: 購入集合 n<100 は「測定不能」
- **機会の大きさを先に測る**: `best_iteration=27` の時点で、検証期 (2024-2025) で 5pt 超の頭数を数えれば「金額試験は成立しない」と実行前に分かった。今回は 2026 窓を消費して初めて分かった

### 2. 該当 0 頭は「不合格」か「測定不能」か

**測定不能**。対象集合が空なので回収率も CI も定義されない。総合 **不合格** は主要仮説だけで成立しており、そこに誤りはない。書き方は「金額: 該当 0 頭で測定不能。対照 70.3% は市場の性質。総合: 主要仮説により不合格」。付随する設計欠陥: 仮に主要仮説が合格しても、0 頭なら代替規則で全頭 (~70%) に落ちて金額は自動的に不合格になる。**この事前登録では合格が構造的に不可能だった。**

### 3. 70.3% は理論値 80% より 10pt 低い — 何を意味するか

**計算誤りではない。「人気薄の混入」= 均等買いの構造そのもの**。80% は投票金額で重み付けした平均。`stake ∝ 1/odds` で測ると **77.0%**。1 頭 100 円均等は市場より人気薄に過大配分する。

| 人気 | 頭数比 | 回収率 (鮮度内) | 回収率 (全窓) |
|---|---|---|---|
| 1 | 7.6% | 83.2% | 79.0% |
| 2-3 | 15.0% | 79.3% | 78.2% |
| 4-6 | 22.7% | 63.4% | 72.0% |
| 7-9 | 21.8% | 76.0% | 68.9% |
| 10 以下 | 32.8% | 65.6% | 55.5% |

頭数の 1/3 が 10 番人気以下で回収 55-66%。これが平均を引き下げる favourite-longshot bias。**対照は市場比例 (~77%) か 1 人気ベタ (~80%) を置くべき。**

### 4. 「30 特徴セットを外す」は妥当か

**妥当。ただし根拠は有意性ではなく大きさ**。β₂ の検出力不足 (MDE≈1.83) のため「区間が 0 を含む」だけでは外せない。外せる理由は **モデルを完全に信じても (β₂=1 と仮定しても) 金にならない**こと:

- `p_off / p_t10` の最大 **1.557**。損益分岐 (≥1.25) 到達 110 頭、**140% 級 (≥1.75) は 0 頭**
- `EV = p_off × odds_T10` > 1.0 が 89 頭、> 1.2 が **3 頭**
- 市場帯別の最大相対補正: 0-5% 帯 1.557 / 5-10% 1.364 / 10-20% 1.246 / 20%+ 1.16 以下
- 探索的 (判定外): 相対補正上位 10% (827 頭) の均等買い 72.4% — 全頭 70.3% と差なし

留保 2 件: (i) 2026-05-09〜08-31 は 0.5-3 / 0.5-4A で消費済み。0.5-5 の特徴選定を同窓で行うと選定ステップが in-sample になる。(ii) 早期停止 27 本は skew 込みで、より厳格な設定なら補正はさらに小さくなる方向。

## 反証の試み

- 「70.3% は正しい」→ 独立再導出 70.8% [61.0, 80.5]。**成立**
- 「補正は 1pt 超 239 / 2pt 超 30 / 3pt 超 6 / 5pt 超 0」→ 平均・最大・0 頭は一致。ただし **239 / 30 / 6 は正方向のみ**。絶対値なら 554 / 63 / 10 (負方向 315 / 33 / 4)。RESULTS の `|補正後 − 市場|` 表記と不一致
- 「金額 → 不合格」→ 対象集合が空、表示値はモデル非依存の対照。**不成立** (測定不能が正しい)
- 「最も有利な形でも再現された」→ 検出力上は β₂=1 も排除できていない。しかし相対補正 ≥1.75 が 0 頭という大きさの証拠で実質は **成立**

## 主な改善提案

1. **金額判定の三値化と対照の分離** — `flat_bet_edge` が None なら `money_pass = None` ("untestable")、`flat_bet_all` を `control_flat_all` に改名。`verdict.overall_pass` は primary と (money が None でない場合の) money で決める。
2. **0.5-5 事前登録の金額条件を完備** — 対象集合は **`p_off/p_mkt` 比で定義** (5pt 絶対値は低確率帯で 140% 級を逃し高確率帯で甘い)、最小 n=100、対照 = 市場比例 (~77%) と 1 人気ベタ、検出力 (MDE) の事前計算、機会数を **検証期で事前測定** (2026 窓に触れず)。
3. **監査証跡** — 1 回目 JSON を `_run1.json` で保存、`run_index` を実回数に。事前登録の修正は単独 commit で run の前に置く。
