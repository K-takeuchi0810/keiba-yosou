## 1 回目の判定 (v1) を不合格にしたのは、私のスクリプトの頭数の定義の誤り

1 回目は 5 か月 (2022-01 / 2023-01 / 2023-02 / 2025-03 / 2025-11) が「順位 > 頭数 + 2」で不合格だった。
スクリプトが頭数を **確定着順のある行の数** で数えていたため、競走中止 (異常コード 4) の馬がいるレースで頭数を
少なく数えていた。該当の 7 行 (対象外の 2026-08 の 1 行を含む) をすべて調べると、いずれも競走中止の馬が 3〜5 頭いる
レースで、通過順位は本番の `races.starter_count` (出走頭数) 以下だった (例: 2025-11-22 京都 8R の 3 角 18 位は 18 頭立て)。
事前登録 §8-3 の定義は「4 角の順位 > 出走頭数」なので、頭数を「取消・除外 (1/2/3) を除く行数」に直して判定だけをやり直した
(v2)。取り込みはやり直していない (v1 と v2 で取り込みの件数とチェックサムは同一、月ごとの値で違うのは範囲外の件数だけ)。

**訂正 (validation レビュー)**: 初稿は「判定は初版より厳しい」と書いたが不正確。v1 → v2 は (a)「+2」の緩みを外した (厳しくなる) と、
(b) 頭数を「確定着順のある行」から「取消・除外 (1/2/3) 以外の行」に広げた (緩くなる) の混合の変更で、5 か月の不合格を
合格に変えたのは (b) である。v2 を正当化するのは厳しさではなく、事前登録 §8-6 の返還の規則 (1/2/3 は有効な出走馬でない) と、
本番の `races.starter_count` との一致 (取消・除外を除く行数 == starter_count が 18,999 / 19,056 レース、不一致 57 はすべて
中止 (data_div 9、starter_count 0)。clone の 262,113 行で順位 > starter_count は 0 件)。
