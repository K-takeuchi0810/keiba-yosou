## 1. 何を作るか

市場オフセットモデル。

```
logit(P_true) = logit(P_market_T10) + AI 補正
```

LightGBM の `init_score = logit(P_market_T10)` で学習する。教師は実際の着順のみ。
**最終市場は教師にも特徴にも使わない。**

## 2. 学習・検証・評価の分離 (0.5-3 から変更しない)

| | 期間 |
|---|---|
| 学習 | 2021-01-01〜2023-12-31 |
| 検証 (早期停止・構造決定) | 2024-01-01〜2025-12-31 |
| 評価 | 2026-05-09〜2026-08-31 |

**問題**: 2021-2025 には `odds_snapshots` が無い (2026-05 以降のみ)。
つまり学習期間に T−10 市場価格が存在しない。

**対処**: `horse_races.win_odds` を市場価格として学習する。ただしこの列は
確定オッズではない (0.5-3 で判明、勝ち馬の 47.8% が確定払戻と不一致)。
**学習時の市場価格には系統誤差が入る**ことを承知の上で使う。
評価時は T−10 の `odds_snapshots` を使うので、train-serve skew が残る。
**この skew は 0.5-4 の結論を弱める方向に働く** (学習時の市場が実際より
不正確 → 補正が過大に学習される) ので、正の結果が出た場合は割り引いて読む。

## 3. 主分析の集合 (実行前に固定)

- T−10 スナップが **発走 30 分前以内** のレースのみ (0.5-3 実測で 626 レース)
- 馬集合が T−10 / 最終 / モデルで一致するレースのみ
- 出走取消 (`abnormal_code='1'`) の馬は除外、発走除外・競走除外は敗者として残す
- 中止レース (`data_div='9'`) は除外
- 学習データの信頼下限は 2021-01-01

## 4. 合格条件 (これを満たさなければ不合格)

### 4-1. 確率の質 (主要仮説)

**条件付きロジット (Benter 型) で、市場価格を与えた上での AI 補正の係数が
正で、レース単位ブートストラップ 95% 区間が 0 をまたがないこと。**

```
P(i が勝つ) ∝ exp(β₁·logit(P_market_T10) + β₂·AI補正)
合格: β₂ > 0 かつ 95% 区間の下限 > 0
```

補助指標 (合否は決めない):

- LogLoss が **0.21351 を下回る** (鮮度 30 分以内・626 レースでの T−10 市場)
- 帯別較正 (0-5 / 5-10 / 10-20 / 20-30 / 30%+) のずれが市場より大きくない

### 4-2. 金額 (最終的な合否)

100 円均等、払戻は **確定値** (`payouts`, data_div=2) で:

**回収率の 95% 区間の下限が 100% を超えること。**

点推定が 140% でも区間下限が 100% 未満なら **不合格**。
憲法の「CI 下限で判断する」に従う。

### 4-3. 事前に決めた棄却条件

次のいずれかに当たったら、その時点で不合格として記録する。

- 補正が市場価格そのものの単調変換にしかなっていない (β₂ の寄与が
  logit(P_market) に対する非線形項で説明できてしまう)
- 鮮度 30 分以内の集合で負けているのに、全体 (931 レース) では勝っている
  → 古いオッズに勝っているだけ
- 特徴に市場由来が 1 つでも混入している (`assert_no_market_features` が例外)

## 5. 仮説の数と多重比較

事前に立てる仮説は以下の **7 個**。

1. 条件付きロジットの β₂ > 0 (主要)
2. LogLoss < 0.21351
3〜7. 帯別較正 5 帯

主要仮説 (1) は単独で評価する。補助 (2)〜(7) は Bonferroni で
有意水準 0.05/6 (z ≈ 2.64) を用いる。

**この表に無い切り口で良い数字が出ても、それは探索的所見として記録するだけで、
合格の根拠にはしない。**

## 6. 実行回数

主分析は **1 回**。コードの不具合で再実行する場合は、理由をこの文書に追記する。
「条件を変えて出し直す」は探索的所見に格下げする。

## 7. 予想される結果 (先に書いておく)

0.5-3 の結果から、**β₂ の区間は 0 をまたぐ可能性が高い**と予想する。

- Fundamental 単体では条件付きロジット +0.0320 [−0.1279, +0.1845] だった
- 30 特徴は全件が馬柱に載る公開情報で、市場が確実に織り込んでいる
- 先読み (+0.169) は実在するが、結果の説明には足していない

**予想が当たった場合、それは失敗ではなく「この特徴セットでは足りない」という
確定した知見**として記録し、0.5-5 以降で「市場が織り込みにくい情報」
(タイム指数・上がり・展開/脚質 × メンバー構成・クラス昇降・乗替り等) を
足す方向に進む。

先に予想を書いておくのは、結果が出てから「想定内だった」と言わないため。

## 実行記録

### 1 回目: 2026-09-19

事前登録どおり実行。結果は `data/backtest/20260919_phase05_4A_market_offset.json`。

- 主要仮説: β₂ = **+0.3862**、95% 区間 **[−0.8301, +1.7316]** → **不合格** (0 をまたぐ)
- 補助 1: LogLoss 0.21363 (基準線 0.21351) → 下回らなかった
- 金額: 事前登録の購入条件 (補正後が市場より 5pt 以上高い馬) に該当する馬が
  **0 頭**。鮮度内の全頭では 70.3% [61.7, 80.1] → **不合格**
- 棄却条件 2・3: 該当なし

**総合: 不合格。**

### 2 回目: 2026-09-19 (バグ修正のため。§6 の定めに従い理由を記録)

**主要仮説と金額の結果は 1 回目で確定しており、変更しない。**

再実行の理由は **棄却条件 1 の数値計算が壊れていたこと**。`logit(P_T10)` の
3 次項 (−227 まで) と補正 (0.06 程度) を同時に条件付きロジットへ入れたところ、
4 桁のスケール差でヘッセ行列の条件数が跳ね、Newton 法が発散して係数
−2.7×10⁹・区間 10²¹ オーダーという無意味な値を返していた。これは結果ではなく
**バグ**なので、「生き残らない」と読んではいけない。

修正は列の標準化 + 微小リッジ + ステップ制限 (`scripts/fundamental_eval.py`
`conditional_logit`)。既知の係数を復元する試験と、共線列で爆発しない試験を
`tests/test_feature_manifest.py` に追加した。

閾値・集合・購入条件・特徴・モデルは **一切変更していない**。
再実行後に主要仮説と金額が 1 回目と一致することを確認する。
なお棄却条件 1 は「主要仮説が合格した場合に偽陽性を弾く」ための検査なので、
主要仮説が不合格である以上 **判定には影響しない**。

**2 回目の結果**: 主要仮説 β₂ = +0.3862 [−0.8301, +1.7316]、金額 70.3%
[61.7, 80.1] で **1 回目と完全一致**。棄却条件 1 は修正後 +0.4015
[−0.7774, +1.7059] (主要仮説が不合格なので判定には影響しない)。
0.5-3 の値も不変であることを確認済み。**総合: 不合格で確定。**
