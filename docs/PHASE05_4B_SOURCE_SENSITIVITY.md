**これは 4B の再判定ではなく、明示的な感度分析 (robustness analysis)。事前登録された
確認的な検定ではない。** 0B30 と 0B31 のどちらが正しいかは決めていない。
モデル (4B の `predictor/market_offset_model.txt` / `fundamental_model.txt`)、閾値、評価集合の規則は
4B と同じものを各系列にそのまま当て、**入力の T−10 市場だけ** を差し替えた。
背景は `docs/LIVE_INGEST_DATA_INTEGRITY_AUDIT.md` 3-bis / 3-ter / 3-quater。

- スクリプト: `scripts/t10_source_sensitivity.py` (テスト `tests/test_t10_source_sensitivity.py`)

  - 初版 (`3fea521` の `src_sensitivity_20260926/`) はレビュー是正で置き換えた (git の履歴に残る)。
    是正後も 5 系列の要約はすべて初版と同じ値
- 評価窓: 2026-05-09〜08-31 (4A/4B と同じ)。DB は mode=ro

## 系列

| 系列 | T−10 市場の出どころ |
|---|---|
| `original_mixed` | DB の odds_snapshots そのまま (本番の `predictor.pit_t10.t10_market`) |
| `raw_mixed` | raw の 0B30 + 0B31 から組み直した混合 (DB の同じ秒の上書きの影響を除く) |
| `raw_0B30` | raw の 0B30 だけ |
| `raw_0B31` | raw の 0B31 だけ (5〜6 月の backfill_0B31 の元データを含む) |
| `matched_same_state` | raw_0B30 と raw_0B31 が T−10 に選ぶ状態が同じ市場状態 (発表時刻・単勝票数合計・全馬のオッズが一致) のレースだけ |

raw の扱いは本番の取り込みと同じ意味にした:

- **受信時刻**: 本番の fetched_at の由来に合わせる。0B31 の 6/28 以前 (backfill) は **ファイル名の epoch**
  (2,325 本)、それ以外 (ライブの取り込み、取り込まれなかった 7 月前半を含む) は **ファイルの mtime**
  (秒未満切り捨て、0B30 6,489 本 + 0B31 1,707 本)。epoch と mtime が違うファイルは 0B30 78 本・0B31 18 本
  (±1 秒)。**epoch を使った場合と比べて、3 つの raw 系列の選択は 1 件も変わらない**
  (`selection_differs_if_epoch_used` = 0)。同じ秒に両方の取得元がある件数は 29 (epoch では 28)
- odds > 0 の馬が 0 頭の O1 は本番で行を作らないので「存在しない」とみなす (該当 0 件)
- 選択は `t10_market` と同じ「決定時刻以前で受信が最新の 1 枚」で、それより前の枚へは遡らない
- raw_mixed で同じ秒に両方ある場合は単勝票数合計の多い方、同数なら 0B31
- **本番との等価性**: 組み立て (`build_market`) は `t10_market` の写しなので、起動時に評価窓の
  全 1,176 レースで「DB の行を build_market に通した結果 == 本番 t10_market」を確かめた
  (選んだ枚・受信時刻・発表時刻・各馬のオッズ・違反・欠損の扱いまで)。**不一致 0**
  (両方とも欠損 239)。1 件でも違えば分析を始めずに止まる
- 名前が二重の raw (`*.jvd_*.jvd`、1,980 本) はすべて 0 バイト

  そこでの Δβ₂ は −0.049 で、区間は 0 を含まない (小さいが有意な負の方向)。主要仮説の合否は動かない
- raw 系列の β₂ が +0.72 に上がったのは **取得元ではなく集合の違い** (下記の 7 月の 131 レース)。
  raw_mixed の「結論が同じ」は、集合の違いに対する頑健性を示している

### 集合の違いの原因: DB の取り込み漏れ

- 7/04・7/05・7/11・7/12 の 0B31 は raw に 368 本あるが、DB の odds_snapshots に 1 行も無い
  (backfill は 6/28 まで、ライブの取り込みは 7/18 から)。raw 系列はこの 131 レースを加える
  (`LIVE_INGEST_DATA_INTEGRITY_AUDIT.md` 3-ter)
- matched_same_state が 34 レースにとどまるのは、取得間隔の差 (8 月の raw で 0B31 は 1 レース約 2.8 本、0B30 は約 20.3 本) で
  両方が T−10 に同じ状態を選ぶ機会が少ないため

## 結論

- **original_mixed、raw_mixed、raw_0B31 では、coverage 閾値の合理的な範囲 (40〜55%) で
  4B の主要な否定的結論は変わらなかった** (主要仮説は不合格、金額は判定不能、比 ≥ 1.75 は 0 頭、棄却条件なし)
- **raw_0B30 は coverage 47.9%** で、50% 基準では参考扱いだが、45% 基準では判定対象となり
  棄却条件 2 に該当する。ただし変化量は ΔLogLoss +0.00002 と極小で、主要仮説を支持する結果ではない
- **matched_same_state は標本が小さく**、いずれの合理的な閾値でも結論を出せない。したがって
  「同じ市場状態に揃えると差が消えるか / 残るか」は判定できない
- 実際に取得元が入れ替わった 8 月の範囲では、β₂ が小さく (−0.049) 動く。合否を動かす大きさではない
- **4B は mixed-source の T−10 市場に対する結果** であり、取得元の provenance と coverage には既知の欠陥
  (3-bis 同じ秒の上書き、3-ter 7 月前半の取り込み漏れ、3-quater 発表時刻の上書き) があった。
  この注記は今後も残す。今回の感度分析からは、4B を「間違いだった」とする根拠は出ていない
