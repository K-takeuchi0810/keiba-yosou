# 次の世代の候補 A″ — 仕様の前提 (2026-10-06、探索の台帳を開く前・A″ の値を計算する前にコミット)

外部の指示者の決定 (2026-10-06): Phase 0.5-5 の族を閉じた後の次の世代の最初の候補。**Group A をもう一度試すのではなく、Group A の主検定の後に
生まれた次の世代の仕様** である (A の 2025 の結果・検出力の不足の原因・C′ で別の標準化が効いたことを見た後に作った)。したがって 2025 では
確証にできない。**将来の確証の証拠は 2026-10-10 以降の新しい窓 (fresh) だけ** (`docs/LOCKBOX_GOVERNANCE.md`)。

状態: `DEVELOPMENT` (2022-2024 だけ)。この文書は候補の仕様の前提で、開封の条件 (`N_primary_required`・比 r・族と多重比較・金額の成熟) は
候補の門 (§6) を通った後の `CANDIDATE_READY` の事前登録で別に固定する。

## 1. 仮説

Group A と同じ (`docs/PHASE05_5_PREREG.md` §2 A): 走破時計の内容で評価した能力に、確定市場が織り込んでいない情報がある。
変えるのは **能力の尺度の単位** だけで、仮説・評価値の意味は変えない。

## 2. 固定する前提 (外部の指示者の決定の項目)

- **評価値 (Performance Rating)**: Group A の凍結した 1 走の評価値の定義 (S1 / V1 / W0、P3 の改訂 B を含む、秒 / km の残差の符号を反転した値) を
  そのまま使う (`scripts.group_a` の `fit_tables` / `rate_runs`、仕様 `S1V1W0`)。補正テーブルは推定期間ごとに推定し直す (Group A と同じ PIT の規則)
- **成分**: Group A と同じ 4 つ (`perf_rating_last` / `perf_rating_best3_365` / `perf_rating_trend_365` / `perf_rating_rank_in_race`、
  §8-4b の定義・365 日の窓)。成分を足す・減らすことはしない
- **標準化だけを変える**: 成分と合成した S を、Group A の全体の平均・SD ではなく、§8-4c-2 の **pooled within-race SD** で割る
  (ddof 0・1 レース 1 票・分散 0 のレースも含める・市場の重みは使わない・レース平均の引き算もレースごとの z 化もしない)
- **欠損**: 標準化した後、そのレースの欠損でない行の平均で埋める (§8-4c-2 の中立の値)。欠損でない行が 0 頭のレースは全頭 0
  (レース内で一定なので識別に寄与しない)。Group A の「全体で中心化した 0 で埋める」は使わない。件数を年別に記録する
- **合成**: 標準化した成分を、学習期の条件付きロジット `[market_feature, 成分 4 つ]` で合成の重みを決め、逆符号の成分は重み 0
  (Group A の手順 3 と同じ規則)。合成した S_raw を同じ規則の σ_within で割る (β は pooled within-race SD 1 単位あたり)。
  全成分が逆符号なら A″ は候補にならない (止める)
- **市場の項**: `log P_market` (`predictor.race_market.market_feature`、§8-6b)。Group A の logit は使わない
- **対象レースと選択集合**: §8-6 (JRA・`data_div = 7`・平地・勝ち馬 1 頭、返還の除外と再正規化、同着は除いて件数を記録)
- **β_target**: ln(1.25)/2 (§8-4c-2 の定義、pairwise の相対オッズ)。検出力の手順は §8-7b (結果を読まない Fisher の SE と学習期のブートストラップの SE の大きい方)
- **使わないもの**: Group A の 2025 の β (+0.049)・区間・副次の記録を、仕様の選択・閾値・候補の選択に使わない。2025・reserved
  (2026-09-14〜10-09)・fresh (2026-10-10〜) を A″ の開発・診断に使わない (研究の窓の関所が止める)。C′ で within-race の標準化が
  検出力を確保したことは設計の原理として使うが、A″ の効果の証拠にはしない

## 3. 探索の手順 (Phase 0.5-5 の型、2022-2024 だけ)

- 尺度を推定する期間は §8-4c-2 と同じ (評価する側の年を混ぜない): E1 (2022 → 2023 / 2023 → 2022) は当てはめの側の年だけ、
  E2 (2022-2023 → 2024 の dry run) は 2022-2023、凍結は 2022-2024
- 探索の台帳を **A″ の値を計算する前に** 開く。候補は 1 つ (上の仕様)。仕様の選択は無い (S1V1W0 は Group A で固定済み、標準化と市場の項は
  ここで固定済み)。E1 / E2 の結果を見た後に仕様を変えない (変えるなら台帳に改訂として記録し、その版は新しい候補として扱う)
- 実装は `scripts/group_a2.py` (計算) / `scripts/group_a2_explore.py` (探索) / `scripts/group_a2_run.py` (開封の手順、門を通った後) の
  名前で作る (研究の読み込みの静的テストの網に入る)。読み込みは `scripts.group_a.load_races` (研究の窓の関所を通る、目的 `development`、
  2024 まで)。Group A の凍結物・錠・主検定の成果物は読まない (仕様の選択に A の 2025 を使わないため)

## 4. 学習期で必ず記録する量 (候補の門の材料、判定は §6)

- E1 / E2 の β_S と z (符号の安定性)、合成の重みと逆符号で 0 になった成分 (年ごと)
- 市場の確率で重み付けたレース内の S の分散 (1 レースあたり、Group A は 0.26・C′ は 0.83) と、S と市場のレース内の相関
- 2024 の対象の行での結果を読まない Fisher の SE → 1 レースあたりの σ₁ → `N_primary_required = ceil((3.4174·σ₁/β_target)²)`
  (規則の §4。学習期のブートストラップの SE の換算と大きい方)
- 件数の見込み: 2024 の行で `market_clogit.ratio_buys_at(rows, 1.0, β_target)` (100 レースあたりの頭数) と、1,500 点に要するレース数
- 比 r = 2024 の A″ の解析対象のレース数 ÷ 2024 の確定の平地の JRA レース数
- **構造の量 (結果の列を使わない、E1 の前に測る。Group D の教訓)**: 学習期の対象の行で、S_std と前走の着順 (分位) のレース内の相関、
  S_std と log P_market のレース内の相関、S_std を [前走の着順の分位, log P_market] でレース内に線形回帰した決定係数。§2 A の仮説は
  「着順では沈むが内容は良い馬」なので、S が着順の主効果の言い換えにすぎない (決定係数が大きい) なら、主検定は仮説を識別しない。
  仕様を変える材料ではなく、候補の門の材料 (門で落とす)
- §2 A の反証の条件 (「A 単独で条件付きロジットの追加係数が 0 をまたぐ」) は主検定そのもので、学習期の E1 / E2 の係数は記録するが、
  それで仕様を選ばない

## 5. 変えないこと

β_target・99% 区間・比 1.25・最低点数 1,500 は緩めない。Group A の主検定の結果 (`PRIMARY_INCONCLUSIVE`) は書き換えない。

## 6. 候補の門 (`DEVELOPMENT` → `CANDIDATE_READY`、外部の指示者の決定、`docs/LOCKBOX_GOVERNANCE.md` §6)

学習期で符号が極端に不安定でない / pooled within-race の分散が十分 / 結果を読まない検出力で現実的なレース数で `MDE ≤ β_target` /
件数の見込みが金額の試験を将来可能にする水準 / Group A との変更点が明示され、2025 の結果を見て最適化した仕様でない (この文書) /
来歴・変異・レビューを通過 / 主検定の仕様を窓に触れる前にコミット。門で落ちたら窓は開けずに捨て、通過順位版の C へ回す。
門の判定の具体的な閾値 (「極端に不安定」「十分」「現実的」) は、E1 の前に探索の台帳に書く。
