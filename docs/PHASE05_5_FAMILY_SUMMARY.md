# Phase 0.5-5 — 族の総括 (2026-10-06)

事前登録 `docs/PHASE05_5_PREREG.md` (情報集合そのものを変える、5 群 A / B / C′ / D / E) の現在の族を閉じる。外部の指示者の指示
(2026-10-06): 族の現状をコミット → D の PIT の確認 → D の扱い → 族の総括。

## 1. 結論

**Phase 0.5-5 の現在の族では、確定市場に対して事前に意味があると定義した大きさ (β_target) の追加情報を持つ群は見つからなかった (PASS 0)**。
事前登録 §4-3「全部落ちたら 0.5-5 も不合格として記録し、さらに別の情報源を探す。『全部落ちたので基準を緩める』はしない」に従い、
**0.5-5 (現在の族) は不合格として記録する**。基準 (β_target・99% 区間・比 1.25・最低点数) は緩めない。
§4-3 の「全部落ちた」は **PASS 0** として適用する: 主検定を実行したのは A・C′ の 2 本で、B・E は BLOCKED、D は PRIMARY_NOT_RUN。
5 群すべてが否定されたという意味ではない。

- 段階は **観察用のまま** (`BUY_FILTER_DEFAULT.suspended = True` は不変)。紙運用・実弾の候補はない
- 封印の開始 (`SEALED_FROM`) は未定のまま (`None` = 封印を開始していない、変えていない)。確認窓 (`CONFIRM_FROM = 20260914` 以降、
  候補の事前登録の後に 1 度だけ使う) は台帳上未消費で、中身は見ていない (§8-8: 主検定を通った候補の事前登録をコミットするまで使わない)
- 「市場誤価格の検出」(憲法 140%) について、この族から言えるのは「事前登録した 2 本 (A・C′) の特徴から、確定市場に対する搾取可能な誤価格の
  証拠は得られなかった」まで。A は判定不能で「情報が無い」の証拠ではない。D は検定していない
- 「判定不能」は β_target (0.112) についての話。憲法の 140% 級 (比 1.75 ⇔ β = ln 1.75 / 2 ≈ 0.280、β_target と同じ換算) は、A の 99% 区間の
  上限 0.145、C′ の上限 0.033 のどちらの外にもある。A・C′ の 2 本の特徴が **それぞれ単独で** 確定市場に対して 140% 級の大きさの情報を持つという仮説は、A・C′ の 99% 区間で退けられる。これは事前登録の判定 (PASS / FAIL / INCONCLUSIVE は β_target についてだけ定義) ではなく、§8-7 の目安 (β ≈ 0.28 は 140% 級の必要条件の楽観側の目安) に基づく事後の読み。複数の特徴の合成や別の情報集合の 140% 級については何も言わない

## 3. この族で分かった方法論の教訓 (次の世代の設計に引き継ぐ)

1. **標準化の単位**: 条件付きロジットが使うのはレース内の変動だけ。全体の SD で標準化すると分散がレース間に回る (A: 市場で重み付けたレース内の
   分散 0.26)。pooled within-race SD で標準化すると保たれる (C′: 0.83)。検出力の見込みと金額の試験に届く件数も大きく変わる
   (β_target での件数の見込み: A 2.9 / C′ 70 / D 0.6 頭 / 100 レース。ただし数え方が違う: A の 2.9 は §8-8 の「S ≥ 2」の目安で数えた記録
   (撤回済みの数え方で、レース内で正規化した比では約 0)、C′ の 70 と D の 0.6 (2024、pooled 0.67) は `market_clogit.ratio_buys_at`。
   D は `data/backtest/group_d_20261006/structural/structural_check.json`)
2. **市場の項は log P_market**: logit で入れると β_market = 1・β_S = 0 でも市場に戻らず、β_market が 1 から外れる (A の 0.867 の大半はこれ)。
   log なら恒等 (§8-6b)。P_new は 1 つの式で尤度と金額の両方に使う
3. **レース内で一定の量は消える**: 「今回のクラスの要求水準を引く」量は前走の評価値と同値 (D)。前走のクラスの要求水準も、class_move
   (≡ −level(前走) + 定数) を局外に入れると大部分が吸収される。特徴を設計するとき、まずレース内で一定の量を引く・掛ける形になっていないかを確かめる
4. **主効果を局外の列に**: S が単純な主効果 (C′ の脚質、D の前走の評価値) とほぼ同じだと、PASS しても仮説の証明にならず、FAIL しても仮説と測定を
   区別できない。仮説が交互作用なら、交互作用を主検定の量として登録する
5. **反証の条件を探索の前に学習期で測る**: C′ では §2 C の反証の条件に学習期で既に該当していた。仮説の入口として、主検定を登録する前に
   学習期の直接の診断を行う (仕様を変える材料ではなく、主検定を登録するかどうかの門として)
6. **検出力の手順は 2 例で一致した**: C′ で結果を読まない Fisher の SE (0.0194) が主検定の区間の幅から逆算した SE (0.0195) と一致、A でも
   MDE から逆算した SE (0.134 / 3.42 ≈ 0.039) と主検定の区間の幅からの SE (≈ 0.038) が近い。2 例なので一般の保証ではない
7. **規律の型**: 事前登録 → 標準化などの規則のコミット → 探索台帳を結果の前に開く → 実装・変異 → 交差 → dry run → 凍結 → 結果を読まない検出力
   (PRIMARY_DECIDABLE / INCONCLUSIVE) → 錠のコミット → 主検定 1 回 → 2 層の解釈。共通の部品は `predictor/race_market.py`・
   `predictor/market_clogit.py`・`scripts/prereg_runner.py`

## 4. 次の世代の候補 (この族の主検定ではない。新しい窓なしでは確証にしない)

外部の指示者の決定 (2026-10-06):

- **A″**: A の時計の情報を pooled within-race SD の単位で表し直す。A の結果・検出力の不足の原因・C′ の標準化の効果を見た後の仕様なので、
  2025 では確証にできない。2022-2024 で作り、必要なら消費済みの 2025 で 1 回だけ診断として通し、将来の新しい封印窓に持ち越す。
  2025 で通す場合は (a) 2025 の 3 回目の閲覧として `config.CONSUMED_WINDOWS` に記録する、(b) その結果で A″ の変種を選ばない
  (選ぶなら封印窓の事前登録に「2025 で条件付けた」と開示する)
- **通過順位版の Group C**: 学習期の条件 (通過順位から推定した脚質の κ > 0.31 / 通過順位の pace_pressure で §2 C の反証の条件に該当しない /
  脚質の主効果を局外の列に / 主検定の年と多重比較を先に固定) を満たした場合だけ、新しい事前登録の候補にする
- **D′**: 「同じ昇級の幅で内容の差が効く」交互作用を最初から主検定の量として登録する。交互作用の検出力は取り方で変わる (S × 1[昇級] MDE ≈ 0.29 /
  S × class_move ≈ 0.11) ので、十分な新しい標本で。登録した D の S は件数の見込みが 100 レースあたり約 0.6 頭で、1,500 点に約 21〜27 万レース
  (JRA の約 60〜80 年分) が要り、主検定を通っても金額の試験に届かない設計だった。**D′ の事前登録には、件数の見込みを学習期で先に測り、
  1,500 点に現実的な期間で届かない設計は登録しない門を課す**。同じ標準化を使った C′ の見込み (1,500 点に約 2,130 レース) から、A″ や通過順位版の C は
  到達可能性の見込みが立つ点で性質が違う (A″ 自身の件数は未測定)
- 優先順 (外部の指示者): A″ → 通過順位版の C。いずれも新しい窓 (封印窓の蓄積) と、その窓を開く前の事前登録が要る
- 確定市場で効かない特徴を「T−10 なら効く」と読み替えない (情報の時間差は別の仮説・別の事前登録)
