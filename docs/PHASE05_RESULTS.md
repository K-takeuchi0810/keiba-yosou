## Phase 0.5-1: T−10 の PIT 完全性 (完了)

合格条件は「T−10 データがある」ではなく **当時の観測可能情報だけで再現できる**こと。

### 選択規則 (predictor/pit_t10.py)

1. 基準はその時点で認識していた最新の予定発走時刻
2. `decision_time = known_start_time − 10 分`
3. 採用は `data_received_at <= decision_time` を満たす **最新値**
4. `decision_time` より後を「近いから」で採らない
5. 無ければ欠損。後続値で補完しない

守り方 (`predictor/feature_manifest.py`):

2. コードを AST で歩き、**市場語を読む関数** を機械的に検出

検出器の語の持ち方も直した。以前は `\b` 付きの完全語一致だったが、正規表現では
`_` が語文字なので `win_odds` を登録しても `place_odds` や `odds_low` に

### ④ 本題: 市場を与えた上で、AI に価値はあるか

分位表や相関ではなく **条件付きロジット (Benter 型)** を主指標にする。
レース内で 1 頭だけ勝つ構造を使い、`P(i が勝つ) ∝ exp(β₁·logit(P_市場) +
β₂·logit(P_fund))` を最尤で解く。「AI の意見が値動きと相関するか」ではなく
**「市場の価格を与えた上で、AI の意見が結果を説明するか」** を直接測る。
レース内正規化・価格水準・レース固有効果は構造に吸収される。

実装の妥当性は市場の係数が示している。較正された市場なら理論値は 1 で、
実測は +0.937 と +1.015。ずれていない。

### ⑤ 先読み (AI の意見は終盤の金の動きを当てるか)

こちらは **残った**。価格水準 (logit p_T10 の 3 次式) を落とした部分相関:

|---|---|
| 素の相関 | +0.0130 |
| **価格を落とした相関** | **+0.1688** [+0.1151, +0.2178] |

価格帯を揃えた上位三分位 − 下位三分位の ΔMarket も 5 帯すべてで正・0 をまたがず
(+0.125 / +0.288 / +1.017 / +1.652 / +1.852 pt)。

素の相関だけ見て「先読みしていない」と結論するのは **誤り**。交絡している。
Fundamental は人気馬を薄く見るので ΔAI が大きく負 = ほぼ人気馬、そして人気馬は
最後の 10 分に買われやすい。素の分位表は AI の意見ではなく「その馬が人気か」を
見ている。

**ただし ④ と合わせると意味は限定される。**

- AI の不同意は **終盤の値動きを当てる** (+0.169、頑健)
- しかし **結果の説明には足していない** (+0.032、0 をまたぐ)
- パリミュチュエルに CLV は無い。払戻は最終オッズで決まり、T−10 のオッズで
  買えるわけではないので、値動きを当てられること自体は 1 円にもならない
- T−10 の価格は投票が薄く誤差を含むので、真の確率と相関する推定器は
  誤差の縮小分だけ「先読み」に見える (errors-in-variables)

→ **先読みは 140% 戦略の候補にならない。** 「狙った馬ほど配当が縮む」という
コスト警告として働く。

### 0.5-5 に持ち込む宿題

1. **検出力を事前登録に必須化** (SE の見込み・MDE・必要 n)
2. **金額の対象集合を比で定義** (`P_new / P_market` ≥ 1.25 等)。絶対 pt は
   低確率帯で 140% 級を逃し高確率帯で甘い。最低件数 100 を明記
3. **対照を市場比例 (約 77%) と 1 人気ベタ (約 80%) にする**
4. **カウント特徴の非定常性**: `t_runs` / `j_rides` は学習域 [0:1530] /
   [0:2588] を超える行が 2026 窓で **19.7% / 41.0%**。木は域外を定数外挿するので
   2026 の補正の大半は検証済みの関数ではない。直近 365 日窓かクリップに置換する
5. **2021H1 の burn-in**: 学習 142,207 行のうち 2021H1 が 24,375 行 (17.1%)、
   その 26% (約 6,400 行) は 2019-2020 に出走記録があるのに過去成績が「新馬」と
   同じ値。`train.from` を 20210701 にすれば累積は 2021-01-01 から回したまま
   出力だけ burn-in 後にできる (真の冷却 26.3% → 1.3%)
6. **機会の大きさを検証期で先に測る**。今回は 2026 窓を消費して初めて
   「5pt 超が 0 頭」と分かった。検証期 (2024-2025) で数えれば実行前に分かった

## Phase 0.5-4B: 基盤修復の監査 (Foundation Repair Audit)

**これは新しい検証ではない。** 0.5-4A のレビューで露出した土台の欠陥 2 件を
直し、**欠陥が消えたか**を確かめる工程。性能の改善を目的にしない。

**0.5-4A は凍結した。** `data/backtest/baseline_30features_frozen_20260919.json`
に「旧 30 特徴ベースライン」として保存し、以後の修正結果で上書きしない。
3 回実行になった経緯 (数値バグ・コンソールバグの修正) も履歴として残す。

### 直した欠陥 1: 学習域を出るカウント特徴

`j_rides` / `t_runs` は信頼下限 (2021) からの累積で、実質
**「観測窓の経過時間」**を数えていた。木モデルは学習域の外を定数で外挿するので、
そこに入る行の出力は「学習して検証した関数」の値ではない。

**単純な clip では直さない。** clip は「騎乗数 1,000 と 2,000 の違いが分からない」
状態をそのままにして値だけ境界に寄せる。数えている対象を問い直して
**直近 365 日のローリング**に置き換えた。

窓を 365 日にしたのは、2021 を burn-in にすれば 2022 の開始時点で 1 年ぶんの
信頼できる履歴が確保できるため。**2026 の成績は見ずにデータ構造だけで決めた。**

| 特徴 | 学習域外率 (修復前) | 特徴 (修復後) | 学習域外率 (修復後) |
|---|---|---|---|
| `j_rides` | **42.52%** | `j_rides_365` | **2.05%** |
| `t_runs` | **23.24%** | `t_runs_365` | **0.00%** |

分布自体が定常になった (中央値 507 → 470、p75 667 → 667):

| | p50 | p75 | p99 | max |
|---|---|---|---|---|
| `j_rides_365` 学習 (2022-24) | 507 | 667 | 909 | 945 |
| `j_rides_365` 評価 (2026) | 470 | 667 | 1,005 | 1,024 |

残る 2.05% は **上側の裾だけ** (学習最大 945 に対し 2026 最大 1,024)。これは
観測窓の経過時間ではなく **実在の個人差**なので、clip で隠さずそのまま残す。

他の 29 特徴はすべて域外率 1% 未満 (最大 `hd_starts` の 0.15%)。

### 直した欠陥 2: 2021 を burn-in 専用にする

2020 以前の raw がバイト破損で使えないため、2021 年初頭の過去成績は
左打ち切りされていた (学習の 17.1% が 2021H1、その 26% が通算成績「新馬」相当)。

| | 修復前 | 修復後 |
|---|---|---|
| burn-in (学習に使わない) | なし | **2021** |
| 学習 | 2021-2023 | **2022-2024** |
| 検証 | 2024-2025 | **2025** |
| 評価 | 2026-05-09〜08-31 | 同じ |

**burn-in だけでは直りきらないものがある。** 「通算勝率」「通算出走数」は
2020 以前が必要で、2021 を warm-up にしても 2019-2020 に走っていた馬の
キャリアは復元できない。そこで **`h_history_truncated` フラグ**を足した。
JRA の競走馬はほぼ 2-3 歳でデビューするので、**信頼下限の 1 年目に 3 歳以上で
初めて記録に現れた馬**、または **初出時に 4 歳以上だった馬**は、それ以前の
キャリアが見えていない。通算成績が「新馬と同じ値」に見えることをモデルに伝える。

`DATA_SPLIT` が旧 `DATA_PERIODS` と食い違うことになったので、
`config.SPLIT_DIVERGENCE` に理由を宣言し、**宣言の無い食い違いはテストで落とす**
ようにした (旧 train で学習して新 train で評価する in-sample 事故を防ぐ)。

### 修復後に 1 回だけ再評価した結果

**結論は変わらなかった。**

| | 0.5-4A (修復前) | 0.5-4B (修復後) |
|---|---|---|
| β₂ (市場を与えた上での補正) | +0.3862 | **+0.4205** |
| β₂ の 95% 区間 | [−0.8301, +1.7316] | **[−1.0100, +1.6848]** |
| LogLoss (鮮度内) | 0.21363 | **0.21351** |
| \|補正\| 平均 / 最大 | 0.31 / 3.75pt | **0.28 / 3.74pt** |
| `P_offset/P_T10` 最大 | 1.557 | **1.704** |
| 同 ≥ 1.75 (140% 級) | 0 頭 | **0 頭** |
| 補正後 top1 == 市場 1 番人気 | 96.3% | **97.1%** |
| 購入条件 (5pt 超) に該当 | 0 頭 | **0 頭** |

LogLoss は基準線 0.21351 と小数 5 桁まで一致 = **補正が実質ゼロ**。
β₂ の点推定はわずかに上がったが区間は広がっており、判定は変わらない。

**性能が改善しなかったことを理由に修復を戻さない。** データが正しくなった
こと自体が目的で、0.5-4A の結論が土台の欠陥による artifact ではなかったと
確認できたことに意味がある。

### この工程で言えること

- 0.5-4A の「30 特徴では市場を超えられない」は、**学習域外の外挿や
