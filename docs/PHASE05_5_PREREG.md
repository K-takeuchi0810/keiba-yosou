# Phase 0.5-5 事前登録 — 情報集合そのものを変える (2026-09-19)

憲法 `docs/CHARTER_2026_09_17.md` の下で、**特徴を 1 つも実装する前に**、
何を作るか・なぜそれが市場に未反映になりうるか・何をもって採否を決めるかを固定する。

## なぜこの段階に来たか

Phase 0.5-4A が **不合格**。ただし根拠の書き方には注意が要る
(初稿で誤り、レビューで是正した)。

**確定市場に対しては強い否定**: 検証 N=94,709 でオフセット後の LogLoss 改善は
−0.000084、95% 区間 [−0.000193, +0.000019] で 0 をまたぐ。払戻は確定オッズで
決まるので、**この 30 特徴から回収率エッジは原理的に出ない**。

**T−10 市場に対しては未検定**: 学習期 (2021-2025) に T−10 のオッズが無いため、
学習の土台は確定オッズだった。T−10 固有の非効率は原理的に学べない設計で、
主要仮説 β₂ = +0.3862 [−0.8301, +1.7316] は検出力 34% (β₂=1 に対し) の
**未検出**であって反証ではない。

**外す判断の根拠は「大きさ」**: モデルを完全に信じても `P_offset / P_T10` の
最大が 1.557 で、**140% に必要な 1.75 倍が 626 レースで 0 頭**。補正後 top1 の
96.3% が市場 1 番人気と一致し、モデルは市場をほとんど動かしていない。

30 特徴は **全件が馬柱に載る公開情報** で、市場が確実に見ているものだった。

> モデルを強くする段階ではなく、モデルに与える情報そのものを強くする段階へ

したがって禁止事項を先に書く。

### やらないこと

- LightGBM のハイパーパラメータ調整
- 閾値の変更・探索
- 特徴の重みいじり
- 既存 30 特徴の組み替え
- **回収率を見ながらの特徴選択**

### やること

「市場に既に織り込まれている公開情報を追加する」のではなく、
**市場が評価しづらい相互作用を数値化する**。

## 1. 特徴を作る前に仮説を書く (この順序を守る)

すべての特徴は次の形で登録してから実装する。

```
Feature: <名前>
仮説: <なぜ市場に未反映になりうるか>
元データ: <テーブル・列>
available_at: <この値が確定する時刻。T−10 より前であること>
市場が見落とす理由: <公開情報なのになぜ価格に入らないのか>
反証条件: <何が観測されたらこの仮説を捨てるか>
```

「使えそうだから追加」は禁止する。これをやらないと数百特徴を探索して
**偶然 140% になった組み合わせを拾う**。

## 2. 特徴群 (5 群。群ごとに別々に検証する)

### Group A — 能力を「着順」ではなく内容で評価する

**仮説**: 市場は着順と人気を強く見る。しかし「どの時計・展開・相手・馬場で
その着順だったか」の補正は手間がかかるため、**平均的な投票者は粗くしか
行わない**。特に **負けたが内容は良かった馬** は着順ベースの評価で沈み、
価格が実力より安くなりうる。

作るもの: `Performance Rating`

    補正走破タイム = 生タイム
                    − 距離補正 − 馬場差補正 − ペース補正
                    − クラス補正 − 斤量補正 − 競馬場補正

| 特徴 | available_at | 元データ |
|---|---|---|
| `perf_rating_last` | 前走確定時 | horse_races.finish_time ほか |
| `perf_rating_best3` | 同上 | 同上 |
| `perf_rating_trend` | 同上 | 同上 |
| `perf_rating_rank_in_race` | 出走表確定時 | 同上 |

**反証条件**: Group A 単独で条件付きロジットの追加係数が 0 をまたぐ。

### Group B — 上がりを単独で使わない

**仮説**: 「上がり 3F 33.5 秒」は誰でも見られるので市場も認識する。
しかし **同じ上がり上位でも意味が違う**。

- ハイペースを前で受けて上がりも上位 = 強い
- スローペース最後方から上がり最速 = 展開の産物

この区別には前半ペース・位置取り・馬場・距離を掛け合わせる必要があり、
**手間の分だけ価格に入りにくい**と考える。

作るもの: `Race Context-adjusted Closing Performance`

    上がり順位 × 前半ペース × 位置取り × 馬場 × 距離

| 特徴 | available_at | 元データ |
|---|---|---|
| `closing_adj_last` | 前走確定時 | horse_races 通過順・上がり |
| `closing_vs_pace` | 同上 | 同上 + races |
| `closing_from_front` | 同上 | 同上 |

**反証条件**: 素の上がり順位を入れた場合と比べて追加係数が増えない
(= 文脈補正に意味が無い)。

### Group C — 展開はその馬単独でなくレース全体から作る

**仮説 (最重要)**: 脚質ラベル (逃げ/先行/差し/追込) だけでは足りない。
知りたいのは **「今回その脚質が有利か」**。

`Pace Pressure`: 逃げ・先行馬が多いレースでは、過去着順から推定される
先行馬の勝率を **市場が過大評価する**可能性がある。前に行く馬が揃えば
前が潰れるが、各馬の過去成績は「前に行って好走した」記録なので、
メンバー構成を跨いだ補正は個々の馬柱からは読み取りにくい。

レース全体から作るもの:

| 特徴 | available_at | 元データ |
|---|---|---|
| `expected_front_runners` | 出走表確定時 | 各馬の過去通過順 |
| `expected_stalkers` | 同上 | 同上 |
| `pace_pressure` | 同上 | 同上 |
| `front_competition` | 同上 | 同上 |
| `closer_ratio` | 同上 | 同上 |

各馬について:

| 特徴 | 意味 |
|---|---|
| `style_x_pace_fit` | `horse_style × race_pace_structure` |
| `style_rarity_in_race` | その脚質がレース内で希少か |

**反証条件**: `pace_pressure` の高い群で先行馬の実勝率が市場の含意を
下回らない (= 過大評価が存在しない)。

### Group D — クラス昇降を着順と組み合わせる

**仮説**: 「昇級だからマイナス」は市場も同じように割り引く。差が出るのは
**同じ昇級でも中身が違う**ところ。下級条件を圧勝しての昇級と、ぎりぎり
勝ちでの昇級は別物だが、**着順は同じ 1 着**なので市場の割引は似た大きさに
なりやすい。

作るもの: `Class Delta`

    前走 Performance Rating − 今回クラスの要求 Performance

「この馬は今回のクラスでも能力値が足りるか」という形にする。

| 特徴 | available_at | 元データ |
|---|---|---|
| `class_delta` | 出走表確定時 | Group A + races.grade_code / 条件 |
| `class_move` | 同上 | 同上 |
| `class_delta_x_move` | 同上 | 同上 |

**反証条件**: `class_move` 単独と比べて `class_delta` の追加係数が増えない。

### Group E — 乗替りも騎手勝率だけで見ない

**仮説**: 「ルメールだから +1」は市場に織り込まれやすい。差が出るとすれば
**この馬・このコース・この脚質に対する相性の変化**であって、騎手の総合勝率
ではない。

作るもの: `Jockey Change Delta`

    (新騎手の適性) − (旧騎手の適性)
      適性 = コース適性 × 距離適性 × 脚質相性 × 当該馬との過去相性

| 特徴 | available_at | 元データ |
|---|---|---|
| `jockey_change` | 出走表確定時 (騎手変更は JC レコードで追える) | horse_races.jockey_code |
| `jockey_delta_course` | 同上 | 同上 |
| `jockey_delta_style` | 同上 | 同上 |
| `jockey_horse_history` | 同上 | 同上 |

**反証条件**: 既存の `j_winrate` を入れた上で追加係数が 0 をまたぐ。

## 3. PIT 保証 (今回の事故を踏まえた必須要件)

0.5-3 で **同日別開催の未来の結果が特徴に混入**していた (調教師 20.1% /
父 31.4%)。同じことを新特徴で繰り返さない。

**すべての新特徴に `available_at` を持たせ、`available_at <= decision_time`
をコードで検査する。**

特に危険な例を先に潰しておく:

- **馬場差指数**: レース後に後付けで更新される馬場指数を過去の予測に使うと
  リークになる。**その日のその時点までに確定した値だけ**を使う
- **ペース補正**: 当該レースのペースは走ってみないと分からない。
  当該レースには **予想ペース** (メンバー構成から作る) しか使えない。
  過去走の補正には実ペースを使ってよい (既に終わっているので)
- **クラス要求 Performance**: 当該クラスの過去実績から作るが、
  **当該レースを含めない**

登録先は `predictor/feature_manifest.py`。各特徴について
`feature_name / source_table / source_columns / transformation /
market_dependency / available_at / hypothesis / falsification` を持たせる。

## 4. 検証手順 (回収率から特徴選択しない)

### 4-1. 群ごとに、市場を条件とした追加説明力を測る

**いきなり回収率を見ない。** 主指標は条件付きロジットの追加係数。

```
P(i が勝つ) ∝ exp( β_market·logit(P_T10)
                 + β_A·GroupA
                 + β_B·GroupB
                 + ... )
```

段階的に:

| 段階 | モデル |
|---|---|
| 0 | `Market only` |
| 1 | `Market + A` |
| 2 | `Market + B` |
| 3 | `Market + C` |
| 4 | `Market + D` |
| 5 | `Market + E` |

**最初から全部 LightGBM に投入しない。** 何が市場に対する edge を作って
いるのかを特定できなくなる。

→ 2026-10-04 改訂: この式の `logit(P_T10)` は運用への移植の確認用。主検定の市場は確定オッズ (§4-5「基準市場を
二分する」、§8-5)。

### 4-2. 採否の条件

各群について:

**その群の追加係数が正で、レース単位ブートストラップ 95% 区間の下限が
Bonferroni 補正後も 0 を超えること。**

群は 5 つなので有意水準 0.05/5 (両側 z ≈ 2.58)。

→ 2026-10-04 改訂: 上の「95% 区間の下限が Bonferroni 補正後も」は内部矛盾 (95% 区間は α = 0.05) なので撤回する。
主検定の判定は **両側 99% パーセンタイル区間 (レース単位ブロック・ブートストラップ、n_boot = 5000、
seed = 20261004) の下限 > 0** (§8-4)。

**ここで情報量が無い群は落とす。** 回収率が良くても残さない。

### 4-3. 生き残った群だけを Market Offset Model に渡す

全部落ちたら、0.5-5 も不合格として記録し、さらに別の情報源を探す。
「全部落ちたので基準を緩める」はしない。

### 4-4. 金額は最後に 1 回だけ見る

生き残った群で作ったオフセットモデルについて、100 円均等・確定払戻で
回収率の 95% 区間の下限を見る。**特徴選択には使わない。**

## 4-5. 0.5-4A のレビューで判明した必須項目 (2026-09-19 追記)

事前登録に書いていなかったために 0.5-4A で問題になった点を、先に埋めておく。

### 検出力を先に書く (必須)

0.5-4A は SE(β₂) ≈ 0.647、80% 検出力の最小検出差 ≈ 1.81、β₂=1 での検出力 34%
だった。**「補正を額面どおり信じる」対立仮説すら検出できない設計**で走らせて
しまった。0.5-5 では各群について次を **実行前に** 書く。

- SE の見込み (0.5-4A の実測から外挿してよい)
- 80% 検出力の最小検出差 (MDE)
- 想定する効果量での検出力
- 検出力が足りない場合、何をもって「判定不能」と記録するか

### 金額の条件を完備する

0.5-4A は購入条件を書いておらず、後から 0.5-3 の公表値を流用した。さらに
「該当 0 頭なら全頭にフォールバック」という実装で **合格が構造的に不可能**だった。

| 項目 | 0.5-5 での定義 |
|---|---|
| 対象集合 | **`P_new / P_market_T10` ≥ 1.25** (比で定義。絶対 pt は低確率帯で 140% 級を逃し高確率帯で甘い) |
| 最低件数 | **100 点**。これ未満は「不合格」ではなく **判定不能** |
| 対照 1 | 市場比例 (`stake ∝ 1/odds`、実測 約 77%) |
| 対照 2 | 1 番人気ベタ (実測 約 80%) |
| 合格条件 | 対象集合の回収率 95% 区間の下限 > 100% |
| 全頭均等 | **対照ですらない** (モデル非依存)。参考値としてのみ載せる |

**検出力 (2026-09-19 追記。4-5 が自ら義務化した項目を金額試験に適用していなかった)**

`≥1.25` 集合の 1 点あたり払戻の SD は実測 7.6〜8.4 (平均オッズ 44〜68 倍)。

| n | SE | 95% 区間の半幅 | 下限 > 100% に必要な点推定 |
|---|---|---|---|
| 100 | 約 0.76 | **約 ±150pt** | **約 250%** |
| 400 | 約 0.40 | 約 ±78pt | 約 178% |
| 1,500 | 約 0.20 | 約 ±40pt | 約 140% |

→ **100 点は「区間が定義できる下限」であって「140% 級を検出できる下限」ではない。**
真の 140% を n=100 で検出する力は 10% 未満。**100〜1,500 点の帯は
「判定不能 (検出力不足)」と記録する**。合格を主張してよいのは 1,500 点以上。

参考: 0.5-4B の発生率は `≥1.25` が 57 / 626 鮮度レース = 9.1 頭/100 レース。
100 点に約 1,100 レース、1,500 点に約 1.6 万レースが要る。現在の窓は 626 なので、
**現モデルでは金額試験に到達しない**。4-5 の「検証期で機会数を先に数え、
届かなければ評価窓を消費せず落とす」で正しく処理される。

留意: 検証期 (2025) の `P_market` は確定オッズ、評価窓は T−10 なので
**件数は一致しない** (確定側が引き締まっている分、検証期の件数は過小に出る)。
検証期の件数は **下限の目安**として扱う。

判定には使わないが、`≥1.25` 集合について
**「実勝利数 / Σp_new / Σp_T10」を観察記録として残す** (n<100 でも裾の較正を
追跡できる。0.5-4B では 0 / 1.80 / 1.38)。

### 機会の大きさを検証期で先に測る

0.5-4A は **2026 窓を消費して初めて**「5pt 超が 0 頭」と分かった。検証期
(2024-2025) で数えれば実行前に分かった。0.5-5 では各群について、
**評価窓に触れる前に検証期で対象集合の件数を数える**。100 点に届かなければ
その群は評価窓を消費せずに落とす。

→ 2026-10-04 改訂: 上の「100 点に届かなければ落とす」は撤回し、§8-8 が優先する (検証期の件数は確定オッズでの
下限の目安なので、それで群を落とさず、封印窓の判定日を決める材料にする)。

### 基準市場を二分する

0.5-4A で判明したとおり、`horse_races.win_odds` は **2021-2025 では確定
オッズ** (一致率 99.5%+、不一致は全件同着)、2026 のみ 77.4%。したがって:

| 仮説 | 基準市場 | データ | 状態 |
|---|---|---|---|
| **対 確定市場** (払戻に直結) | `horse_races.win_odds` 2021-2025 | N ≈ 94,709 で検定可能 | 0.5-5 で実施 |
| **対 T−10 市場** (購入判断) | `odds_snapshots` 2026-05 以降のみ | 学習窓に存在しない | **現状は検定不能**。蓄積待ち |

**この 2 つを混ぜない。** 0.5-4A の初稿は混ぜて「最も有利な形でも」と書き、
結論を過大にした。

### 既存の土台に残っていた欠陥 → **Phase 0.5-4B で是正済** (2026-09-19)

1. ~~カウント特徴の非定常性~~ → 365 日ローリングに置換。42.52% / 23.24% →
   2.05% / 0.00%
2. ~~2021H1 の burn-in~~ → **2021 年まるごとを burn-in 専用**にし、学習を
   2022 から始める。「過去成績が新馬と同じ値」は 4.5% → 0.08%
3. `h_history_truncated` を追加。**初版は年齢ヒューリスティクスで、発火率が
   82.4% → 1.8% と時間の代理変数になっていた** (今回潰そうとした欠陥クラスを
   別名で増やしていた)。2020 以前の血統登録番号は無傷なので、DB の真値で
   定義し直した

**残る既知の skew (0.5-5 でも引き継ぐ)**: 学習行の 21.3% (2022 年の行では
36.7%) は 2019-2020 に出走記録があり、通算成績が左打ち切りのまま。
2020 以前の raw は復元できないのでフラグで印を付けるに留める。
→ **2026-10-04 にこのフラグをモデル入力から外し、監査用の列にした** (§8-1)。

詳細は `docs/PHASE05_RESULTS.md` の「Phase 0.5-4B」節。

## 4-6. 2026-09-19 改訂: 基盤欠陥の是正を反映 (Phase 0.5-4B 実施済)

**変更理由は「基盤欠陥の是正」のみ。** Group A〜E の仮説・Bonferroni・
採否基準は **一切変更しない** (都合よく緩めないため、ここに明記しておく)。

Group A の実装前に、0.5-4B で土台を先に直した。差し替わったのは次の 3 点。

### (1) 学習・検証期間 (burn-in の導入)

| | 旧 | 新 |
|---|---|---|
| burn-in (学習に使わない) | なし | **2021** |
| 学習 | 2021-2023 | **2022-2024** |
| 検証 | 2024-2025 | **2025** |
| 評価 | 2026-05-09〜08-31 | 同じ |

2020 以前の raw がバイト破損で使えず、2021 年初頭の過去成績が左打ち切り
されていたため。365 日のローリング特徴なら 2022 の開始時点で 1 年ぶんの
信頼できる履歴が確保できる。

### (2) 基礎特徴 (累積生涯カウント → ローリング)

`j_rides` / `t_runs` は信頼下限からの累積で実質「観測窓の経過時間」を
数えており、2026 窓で 42.52% / 23.24% が学習域外だった。
**直近 365 日のローリング** (`j_rides_365` / `t_runs_365`) に置換し、
2.05% / 0.00% になった。あわせて `h_history_truncated` フラグを追加。

→ **Group A〜E の新特徴も同じ規律に従う。** 累積生涯カウントは作らない。
新しいカウント系を足すときは、最初からローリング窓か率か機会数にする。

### (3) ベースライン

Group 検証の比較対象は **0.5-4B 修復後の `Market only`**。
0.5-4A の数値 (`baseline_30features_frozen_20260919.json`) は
**旧 30 特徴ベースライン**として凍結し、上書きしない。

### 8-4. 主検定 (群ごとに 1 本だけ)

- 主検定の族は **A / B / C′ / D / E の 5 つ**。各群の主検定は両側 α = 0.01 (Bonferroni 0.05/5)。
  BLOCKED の群が実行されなくても α は緩めない
- 主検定の統計量は、群ごとに **1 つの係数** (合成した指標 S の係数 β) だけ
- **区間 (固定)**: 両側 **99% パーセンタイル区間**、**レース単位** のブロック・ブートストラップ、
  **n_boot = 5000**、**seed = 20261004**。採否は「99% 区間の下限 > 0」。β̂ ± 2.576·SE_boot (Wald) は診断として
  併記するだけで判定に使わない。**95% 区間を「Bonferroni 補正後」と呼ばない** (§4-2 の初稿の記述は撤回)。
  (2026-10-04 実装: 従来の 95% の `block_boot` は変えず、`predictor/eval_stats.block_boot_ci` (水準などを明示) と
  主検定専用の `primary_block_ci` (99% を明示させ、5000 / 20261004 / 1% に固定) を足した。主検定のコードは
  `primary_block_ci` だけを使い、`block_boot` / `coefficient_ci` (95%) を使わない。以下の文の「`block_boot`」は
  この 2 つの関数と共通の再抽出 `_block_resample` を指す)
  現行の `predictor/eval_stats.block_boot` は 95% (2.5 / 97.5 分位) しか返さないので、分位の引数を足す (テスト付き。
  端点は `int(0.005·n)` / `int(0.995·n)` と既存と同じ切り捨て)。収束しなかった再抽出の件数を結果に残し、
  **捨てた再抽出が n_boot の 1% (50 回) を超えたら区間は無効 (NA)** とし、`PRIMARY_INCONCLUSIVE` (理由 `boot_na`) と
  記録する。seed・n_boot・分位を変えた再実行はしない (再実行を許すのは、成分の算出コードの欠陥を特定した場合だけ)
- **判定の区分 (固定)**: 主検定の関心効果を **β_target = ln(1.25) / 2 ≈ 0.112** (学習期の 1 SD あたり。
  +2 SD の馬の比 exp(2β) が購入条件の 1.25 に届く大きさ) とする。検出力を固定する時点で、
  最小検出差 (α = 0.01 両側、検出力 80%) が β_target を超える群は、結果に関係なく `PRIMARY_INCONCLUSIVE`
  (判定不能) と記録する。そうでない群は、99% 区間の下限 > 0 なら `PRIMARY_PASS`、下限 ≤ 0 なら `PRIMARY_FAIL`。
  null の結果を後から「測れなかった」と言い換えない。T−10 の移植の確認の「判定不能」も同じ規則で決める
- **主検定の期間と市場**: 2025 年、確定市場 (`horse_races.win_odds`)。対象集合は JRA (track 01〜10) /
  確定 (`data_div = 7`、中止 `9` を除く) / 勝ち馬が 1 頭のレース / 選択集合は §8-6 のとおり。
  **同着 (勝ち馬 2 頭以上) のレースは尤度から除き、件数を記録する** (2025 で 6 レース。金額は払戻の勝ち馬ごとの額で
  会計する)。実行の前に、集合から落ちるレース・馬の件数を数えて記録する
- **再実行の扱い**: 主検定の再実行は、実行前に欠陥を特定して記録した場合だけ許す。すべての実行を報告し、
  仕様の変更を伴う再実行は主検定と呼ばない (0.5-4A の「本番 1 回 + バグ修正の再実行 2 回」の前例を踏まえる)
- **2025 の位置づけ**: Group A / C′ の仕様は 2025 を見ずに決めるので、β の検定にとって 2025 は仕様に対しては
  標本外である。ただし 2025 は 0.5-4A / 4B / 30 特徴版 (LGBM 系) の早期停止・選択に使った年なので、
  **「新しい OOS の証拠」とは呼ばない**。最終的な確認は封印窓 (§8-8) で行う
- **探索と主検定の関係 (§6 より優先)**: 探索 (学習期 2022-2024 の中での試行・デバッグ) は何回でもよい。
  主検定の仕様を確定した後は、**主検定の実行は群ごとに 1 回だけ**。探索の結果を後から主検定に格上げしない。

- **合成の手順 (A / C′ 共通)**:
  1. 成分の仕様を学習期 2022-2024 だけで決める。試したことは探索台帳
     `docs/PHASE05_5_EXPLORATION.md` に残す (仕様ごとの学習期の係数・符号)
  2. 各成分の **期待される符号を、ここ (§8-4b / §8-4c) に事前に書く**
  3. 学習期の条件付きロジット (市場 + 成分) で合成の重みを決める (入力の成分は、欠損でない学習行の平均・SD で
     標準化し、欠損を 0 で埋めた後の値)。**期待と逆の符号になった成分は重み 0** にして
     記録する (逆符号を合成に取り込まない)。重みの安定性 (学習期のレース単位 bootstrap での符号一致率) も残す
  4. 合成した S を **学習期 2022-2024 の平均・SD で標準化** する (β は「学習期の 1 SD あたり」)。
     成分と S の平均・SD は **欠損でない学習行だけ** で計算し、欠損は標準化した後に 0 で埋める
     (埋めた後の行で計算すると平均が 0 側に引かれる)
  5. dry run: 2022-2023 で 1〜4 を行い (補正テーブルも 2022-2023 だけで推定し直す) 2024 で通す
     (パイプラインの点検。証拠にしない、探索台帳に記録。学習期の中では補正テーブルが各行から見て未来の走も含むので、
     学習期の重み・符号一致率はやや楽観側になることも台帳に書く)
  6. **凍結物** (MANIFEST に sha256): 合成の重み、標準化の平均・SD、補正テーブル (§8-4b)、成分の算出コードの SHA、
     推定コード (条件付きロジットと `block_boot`。収束の基準 = 最適化の方法・反復の上限・許容誤差を含む) の SHA。
     2025 の実行はこれらを読み込むだけで再推定しない
  7. 主検定: 2025 で `β_market·logit(P_market) + β·S` の β を 1 回推定する
- **判定に使わない記録 (事前に登録)**: 学習期の leave-one-year-out (2022 / 2023 / 2024) での β の符号 /
  S と logit(P_market) のレース内の相関 ρ / Group A について、S を前走着順で残差化した版の係数
  (「負けたが内容は良かった馬」の直接の検定。落ちたときに「仮説が違う」と「作り方が違う」を区別するため) /
  S を前走の人気で残差化した版の係数 (「市場が着順を見すぎている」の直接の検定) / 365 日以内の出走数・年齢と S の
  レース内の相関 / C′ について、S を脚質の指示 (逃・先 = −1、差・追 = +1) で残差化した版の係数 (pace と無関係な
  「先行・差し」の市場の偏りが S に乗っていないかの切り分け) (いずれも 2025 で 1 回だけ推定)
- **実行の順序は結果に依存させない**: A → C′ の順。A の結果に関係なく C′ も事前登録の手順で行う
  (D は PIT 確認後、B / E は BLOCKED の解除後)

  - `perf_rating_best3_365`: 365 日以内の上位 3 走の平均 (走が 3 未満なら、ある走の平均)

### 8-4b-2. 2026-10-05 追補: クラスの元データと、クラスの補正の意味 (Group A の実装の前)

欠損の扱い) は変えない。**ただし §8-4b の「当日の馬場差を使うかどうかは、学習期の探索で決めて…」の段落 (同じ競馬場・同じ馬場の

障害の定義は `track_type_code` 51 以上に統一する (§8-4b の「52〜57」は 2021-2025 の実データに現れる値の範囲で、定義としては 51〜59)。

### 8-4b-3. 2026-10-05 改訂: 裾の処理 (P3) を当てる座標の修正 (主検定の前、2025 は未閲覧)

**変更理由**: 探索台帳の固定前処理 P3 (馬ごとの過去走の残差を ±3.0 秒 / km で対称に clip) の **意図** は「1 走の極端な残差の
影響の有界化」だった。しかし 2a で残差の基準からクラスと年齢の区分の水準を引かないため、下級条件・若い世代の走は残差が
もともと遅い側に寄り、**実際の振る舞いはクラス・年齢による系統的な打ち切り** だった (遅い側の clip 率: 新馬 2 歳 26% / 3 歳 32.5%、
未勝利 11〜13%、1 勝クラス 1.4〜2%、3 勝・OP 1% 未満。2026-10-05 prediction-logic の学習期 2021-2024 の診断)。これは P3 の値の
最適さの問題ではなく、P3 の意図と振る舞いの自己矛盾なので、外部の指示者の決定 (2026-10-05、選択肢 B) で、主検定の前に正式に改訂する。

- **2025 の結果・オッズは見ていない** (探索の読み込みは 2024 年以前だけ、コードで強制)
- **新しい P3 (B)**: 残差から、そのレースの期待勝ち時計の局外の補正 (クラス `c` + 年齢の区分 `d`) を一度外した値に ±3.0 秒 / km の
  対称の clip を当て、その後に `c + d` を戻す。評価値 = −(clip(残差 − c − d, −3, +3) + c + d) ÷ 尺度
  - 2a (クラスの水準は評価値に残す、評価値から引かない) は保つ。clip を当てる座標だけを変える
  - ±3.0 秒 / km は変えない。P1・P2・その他の仕様 (候補の 12 通り・選択の規則・疎なセル・窓・成分・合成) は変えない
  - B は 13 個目の探索の軸にせず、全候補に共通の固定前処理として P3 を置き換える
  - 年齢の区分が欠損のレース (`c + d` が作れない) の走は評価値を持たない (2021-2025 で 0 件)
  - 斤量 W1 の推定の外れ値の除外 (実装の細部、`|残差| ≤ 3`) も同じ座標 (残差 − c − d) にそろえる
- **E1 (交差) と E2 (2024 の dry run) は消さずに `SUPERSEDED_BEFORE_PRIMARY` として残し**、新しい P3 で E1 を最初から同じ 12 候補・
  同じ同点の規則でやり直す。前の選択 (S1V1W0) は引き継がない (clip の座標が変われば各候補の S が変わる)。やり直しの選択の結果を
  コミットしてから 2024 の dry run を行い、2024 は引き続き仕様の選択に使わない
- clip 率を **年 × クラス × 年齢の区分** ごとに成果物へ残す (採否の基準にはしない。系統的な打ち切りから裾の処理に戻ったかの監査)
- 経緯: A (仕様のまま固定し、B を感度分析にする) は、P3 の意図を満たさないと分かった仕様を確認の仕様として固定することになるので採らない
- **開示**: この改訂は、旧 P3 での **E1 の 24 個の z と選択 (S1V1W0)、E2 の 2024 の z (−0.38) を見た後** に行った。改訂の動機は
  学習期の clip 率の診断 (候補の z ではない) だが、結果を見た後の変更であることに変わりはない
- **forking path の錠 (2026-10-05 validation の指摘で固定)**:
  - 固定前処理 (P1〜P3) の改訂は **この 1 回限り**。E1b (やり直し) の結果を見て、P1〜P3 や他の仕様を再び変えない
  - E1 (旧 P3) と E1b (新 P3) の z の比較を、仕様の選択にも、主検定の解釈にも使わない
  - E2b (新 P3 での 2024 の dry run) は、2024 の z が E2 で既に見えているので **新鮮な点検ではない** (パイプラインの点検に限る)

### 8-6b. 2026-10-06 追補: P_new の唯一の定義と、市場の項 (C′ から適用、C′ の探索の前)

**P_new は 1 つの式だけで作る**:

`P_new(i) = exp(β_market·log P_market(i) + β_S·S(i)) / Σ_j exp(β_market·log P_market(j) + β_S·S(j))`

(`predictor.race_market.p_new`。P_market は §8-6 の選択集合の中で和 1 に正規化し直した値)

- **市場の項は log P_market にする** (これまでの §4-1 / §8-4 の `logit(P_market)` を、C′ 以降の主検定・検出力・金額の
  すべてで置き換える)。理由: logit で入れると、β_market = 1・β_S = 0 でもモデルの確率は `(p/(1−p)) / Σ` になり、市場その
  ものにならない (本命ほど過大)。log なら β_market = 1・β_S = 0 で P_new = P_market に **ちょうど** 一致する
- **この改訂のきっかけ (隠さない)**: Group A の主検定 (2025、run_index 1) で β_market = 0.867 を観測した **後** に、§8-6 の
  「β_market = 1 の仮定」との不一致を調べて見つけた。β_S の推定値・区間は改訂の判断に使っていない。根拠は構造的な要請
  (β_market = 1・β_S = 0 で P_new が市場そのものになるべき) で、裏付けの数値は学習期だけ
- 学習期だけで確かめた大きさ (2025 は読んでいない。Group A の対象の定義で、市場だけの条件付きロジット。再現:
  `data/backtest/eval_refund_20261006/market_term_table.py` → `market_term_table.json`):

  | 年 | レース | β_market (logit) | β_market (log) | β = 1 の平均対数尤度 logit / log |
  |---|---|---|---|---|
  | 2022 | 3,327 | 0.900 | 1.055 | −1.9076 / −1.8982 |
  | 2023 | 3,326 | 0.880 | 1.026 | −1.9429 / −1.9306 |
  | 2024 | 3,321 | 0.895 | 1.047 | −1.8960 / −1.8870 |

  Group A の主検定の β_market = 0.867 (logit) と §8-6 の「β_market = 1 の仮定」の不一致の大半は、この項の入れ方による。
  log で入れると β_market は 1 をわずかに上回る (本命・人気薄の偏りの向き)
- **尤度と金額で同じ係数を使う**: 金額の試験 (T−10、§8-7 / §8-8) の P_new は、主検定の条件付きロジット
  (`β_market·log P_market + β_S·S`、2025 の確定市場で 1 回) が推定した **(β̂_market, β̂_S) の組** をそのまま使い、
  T−10 の P_market に当てる。β_market を 1 に置き換えたり、β_S だけを持ち出したりしない
- 主検定の前の件数の見込み (§8-8) は、同じ関数に仮定値 (β_market = 1, β_S = β_target) を渡して数える (今までどおり。
  2025 の β̂ は使わない)
- 金額の試験の診断 (判定には使わない。結果を見る前にここで宣言する): β̂_market ≠ 1 による本命・人気薄の補正だけで買い目が
  出ていないか、T−10 に移した市場の項の過不足が S の寄与に混ざっていないかを分けて見るため
  - 3 つの集合の比 ≥ 1.25 の件数と重なり (Jaccard): full `P_new(β̂_market, β̂_S)` / 市場の項だけ `P_new(β̂_market, 0)` /
    S だけ `P_new(1, β̂_S)`
  - T−10 の市場だけの条件付きロジットの β_market (移植の確認の窓で、診断として 1 回)
  - 封印窓の金額の試験では、市場の項だけの集合を **対照 3** として先に宣言し、full の集合との差で S の金銭的な寄与を見る
    (回収率を見るのは封印窓でだけ)
- **Group A には遡って当てない**。Group A の主検定・検出力は logit のまま固定・実行済み (954b954)。Group A の検出力の
  計算は「β_market = 1 の仮定で勝つ確率 = P_market」としたが、logit のモデルでは β_market = 1 でも勝つ確率は P_market に
  ならない。この食い違いは Group A の結果の文書に記録として足す (判定の区分は変えない。判定不能は MDE で主検定の前に確定)
- C′ の検出力の入力は C′ 自身の凍結した S・2025 の市場の確率・結果を読まない Fisher 情報だけ (Group A の実測のレース内の
  分散 0.26 は入力にしない。設計上の警告として参照するだけ、外部の指示者 2026-10-06)
- **C′ の凍結の前提条件 (2026-10-06 の 4 名レビューの must-fix)**: Group A のコード (`scripts/group_a.py::add_market_logit`・
  `scripts/group_a_power.py::fisher_se_at_null` の `logit_p_market`) は logit のまま凍結されている。C′ のコードは市場の列を
  `predictor.race_market.market_term` (log) だけから作り、尤度の列・検出力の Fisher 情報・金額の P_new (`p_new`) が同じ関数を通ることを
  テストで強制する。このテストが通るまで C′ の探索台帳を開かない

### 8-7. 多重比較・検出力

- 群は 5 つ (A / B / C′ / D / E) のまま数える。BLOCKED の群が実行されなくても有意水準 0.05/5 は緩めない
- **検出力は各群の実行の前に、その群で実際に使える N と、学習期で作った特徴の値から計算して固定する**
  (S と市場の相関 ρ も併記する)。**検出力の固定に使う SE は、2025 の勝ち馬の列を読まずに出す**: 2025 の S と市場の
  確率だけから、下のシューア補元の Fisher 情報で解析的に計算する (併せて、学習期 2022-2024 のブートストラップの SE を
  √(N_学習 / N_2025) で換算した値も記録し、大きい方を使う)。2025 のブートストラップの SE は、主検定を 1 回実行した後に
  診断として併記するだけ (主検定の前に 2025 で条件付きロジットを当てない)
- 見込み (Group A、実装前の概算): 主検定の 2025 年は 3,455 レース。β_A = 0 での条件付きロジットの Fisher 情報は
  `Σ_レース Σ_馬 p_i (x_i − Σ p x)²` だが、β_market と同時に推定するので実効の情報はシューア補元
  `Var_p(x) − Cov_p(x, z)² / Var_p(z)` (z = logit P_market) になり、市場と相関する特徴ほど小さい。
  市場の確率で重み付けしたレース内分散 v が 0.4〜0.85 のとき `SE = 1/√(3,455·v)` ≈ 0.018〜0.027、
  有意水準 0.01 (両側)・検出力 80% の最小検出差 (3.42 × SE) は **1 SD あたり 約 0.063〜0.092**。
  この見込みは楽観側に寄っている: 2025 の実測の 1 − Σp² は 0.795、S を全体で標準化するとレース間の成分
  (クラス差など) のぶんレース内分散は 0.4 を割りうる。ブートストラップの区間もこれより広くなりうる
  (参考: +2 SD の馬の比 exp(2β) が 1.75 倍 = 140% 級に届くには β ≈ 0.28。ただし exp(2β) はレース内で
  正規化する前のオッズ比なので、これは 140% 級の必要条件の楽観側の目安)
- T−10 の移植の確認 (626 レース) の最小検出差は、その √(3,455/626) ≈ 2.35 倍 (1 SD あたり 約 0.15〜0.22) で、
  β_target (0.112) を超える見込み。§8-4 の規則により、検出力を固定した時点で超えていれば結果に関係なく判定不能と記録する
- **金額試験の予想 (先に書く)**: 主検定が最小検出差の付近で通った場合、比 ≥ 1.25 (`β·z ≥ ln 1.25 = 0.223`) に
  該当する馬は 2025 で約 10〜360 頭しかない。これは件数の目安であって、**2025 の確定オッズでの回収率は買えない価格
  (締切の価格) での値なので、金額の区分は付けない** (実現できない上限)
- **金額の区分は T−10 の窓 (購入条件は `P_market_T10` で定義) にだけ付ける**。消費済みの 626 レースでは診断として、
  判定は封印窓 (§8-8) で行う。区分は次の 4 つに固定する:
  `PRIMARY_FAIL` (または `PRIMARY_INCONCLUSIVE`) / `PRIMARY_PASS × MONEY_UNTESTABLE` (100 点未満) /
  (ここでの `PRIMARY_*` は 2025 の主検定の区分。T−10 の移植の確認が判定不能でも、金額の区分の記録は妨げない)
  `PRIMARY_PASS × MONEY_UNDERPOWERED` (100〜1,500 点) / `PRIMARY_PASS × MONEY_PASS` (1,500 点以上かつ回収率の
  区間の下限 > 100%)。§4-5 の検出力の表から、金額試験は構造的に「判定不能」(100 点未満、または 100〜1,500 点の帯)
  になる見込み。`MONEY_PASS` 以外は「情報はあるかもしれないが、金額は未証明」で、実弾の候補にはしない (観察用のまま)

### 8-7b. 2026-10-05 追補: 検出力の固定の細部 (Group A の主検定の前、2025 は未閲覧)

- **「2025 の勝ち馬の列を読まずに」の意味の明確化**: 検出力の計算で、**主検定の対象レース自身の結果** (着順・勝ち馬・払戻・走破タイム・
  上がりなど) を対象の行に載せず、条件付きロジットに渡さない。対象レースは列の allow-list (返る列の名前の完全一致を実行時に確かめる) の
  別の読み込みで作る (`scripts/group_a_power.py`)。一方、S を作るための **過去走の時計** (2025 の中で対象日より前の日のレースの結果、
  その日の馬場差に使う勝ち時計を含む) は特徴の履歴として読む (外部の指示者の決定 2026-10-05)。履歴は (日, 評価値) だけを持つ
- **解析の SE**: β_S = 0・β_market = 1 の仮定 (勝つ確率 = 返還を除いて再正規化した市場の確率) でのシューア補元の Fisher 情報
  (§8-7 のとおり)。S と市場の確率で重み付けたレース内の相関 ρ を併記する
- **学習期のブートストラップの SE (値を今固定する)**: 凍結した S (重みは再推定しない) を固定し、学習期 2022-2024 の対象レースで
  `logit(P_market) + S` の条件付きロジットの β_S を、レース単位の再抽出で **n_boot = 1000、seed = 20261004** 回推定する。
  SE = β_S の再抽出の値の標準偏差 (ddof = 1)。収束しなかった再抽出は捨て、1% (10 回) を超えたら学習期の SE は NA として記録し、
  解析の SE だけを使う。N_学習 = 学習期の対象レースの数、N_2025 = 検出力の行のレースの数 (同着を含むので主検定のレース数以上。
  差は記録する)。学習期の SE は、S の重みと補正テーブルを同じ期間で推定した in-sample の値なので楽観側になりうる (記録する)
- 臨界の倍率は z_{0.995} + z_{0.80} = 2.5758 + 0.8416 = 3.4174、MDE = 3.4174 × max(解析の SE, 学習期の SE × √(N_学習 / N_2025))。
  MDE > β_target (0.1116) なら、主検定は結果に関係なく `PRIMARY_INCONCLUSIVE` と、主検定の前に確定して記録する
  (それでも主検定は 1 回実行して、β と 99% 区間を記録する)
