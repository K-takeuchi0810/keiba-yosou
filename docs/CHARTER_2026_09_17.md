# プロジェクト憲法 — 市場誤価格検出システム (2026-09-17 ユーザ指示)

**この文書はこれ以前のすべての方針文書に優先する。**
`REFORM_2026H2_MARKET_RESIDUAL.md` / `F3_MARKET_RESIDUAL_DESIGN.md` /
`F3_PREREG_2026Q4.md` は本憲法の下位文書として読み替える。

## 最終目標

**実運用における長期回収率 140% 以上**。ただし:

- バックテスト上の数値を 140% に「合わせる」ことを **禁止** する
- 再現性のある市場優位性によって達成できることを **証明** することが目的
- 達成できない場合は数値を作らず、なぜ達成できなかったかを報告する

## 15 の方針 (要約)

1. **勝ち馬予測 AI ではなく、市場価格の誤りを検出する AI とする**。
   市場が過小評価しているケースのみ購入。見送りを積極的な意思決定として扱う。
2. **オッズを敵ではなく最強のベースラインとして扱う**。
   `logit(P_true) = logit(P_market) + AI補正` の構造。学習対象は
   「この馬が強いか」ではなく「市場が何 % 誤っているか」。
3. **Accuracy / 的中率 / AUC を最終目的関数にしない**。
   LogLoss・Brier・Calibration・市場に対する情報利得・期待値・実回収率・
   最大ドローダウン・購入件数・利益の再現性で評価する。
4. **140% を作るエッジの発生場所を特定する**。全条件を 1 モデルで平均化しない。
   単独ルールではなく **血統 × 馬場 × 距離 × コース × 脚質 × ペース × 人気**
   などの交互作用を重点探索する。
5. **人気薄を買うこと自体をエッジと考えない**。購入は必ず期待値で決定する。
6. **オッズなしモデルとオッズありモデルを分離**し、`Edge = P_fund / P_market` を計算する。
7. **時系列データリークを完全禁止**。Random Split 禁止。Walk-Forward。
   発走 10 分前に取得可能だった情報のみ。最終オッズでの購入判定禁止。
8. **完全未使用の Lockbox Test**。学習 / Validation / Strategy Development /
   Final Lockbox を分離。Final は開発完了まで一切見ない。見て修正したら
   そのデータは Final ではなくなる。同じテストで条件変更して 140% を作ることを禁止。
9. **回収率だけでは合格としない**。十分な購入件数・複数開催期間・複数競馬場・
   複数月・異なる市場環境で再現すること。**最大払戻上位 1/5/10 件を除外した
   回収率も必ず報告**する。
10. **回収率には信頼区間を付ける**。Bootstrap で回収率・信頼区間・最大ドローダウン・
    連敗数・年間利益分布を報告。偶然の可能性を評価する。
11. **Bet Selection を Prediction から独立させる**。
    ①確率予測 → ②期待値計算 → ③購入/見送り判断 → ④資金配分 の 4 段階を分離。
12. **不確実性が高い予測は購入しない**。`EV > 1` だけで買わない。予測分散・
    Calibration 誤差・オッズ変動・サンプル数を考慮し、安全余裕がある場合のみ。
13. **購入件数を目的にしない**。1 日 0 レースでも 1 週間 0 でも構わない。
    「今の市場には十分な Edge が無い」と判断できることを重要な能力とする。
14. **探索対象を「勝率」から「市場の弱点」に変更する**。
    群衆がどの条件で間違えるかをモデル化する。
15. **140% を達成できない場合、数値を作らない**。条件変更・対象削減・期間選択・
    特徴量選択・閾値調整で事後的に 140% を作ることを禁止。

## 合格条件

完全 OOS / 時系列 Walk-Forward / 購入時点情報のみ / 実際に取得可能なオッズ /
十分な購入件数 / 複数期間で再現 / 大当たり依存性の検証 / 統計的不確実性の評価 /
データリークなし / テスト期間を見た後の再最適化なし —— これらを満たした上で評価する。
**140% を統計的に確認できないモデルは本番投入しない。**

# 現状との距離 (2026-09-17 時点の実測)

## 140% が要求するもの

パリミュチュエルでは `回収率 = (1 − 控除率) × (真の勝率 / 市場の含意確率)`。
控除率 20% として:

| 目標回収率 | 必要な 真の勝率 / 市場確率 |
|---|---|
| 100% | 1.25 倍 |
| 120% | 1.50 倍 |
| **140%** | **1.75 倍** |

**140% には「市場が 75% 過小評価している馬」を見つける必要がある。**
実測で確認できている最良のセグメントは **1.0-1.5 倍帯の 87.7% = 1.10 倍**
(`SIM_CEILING_2026_09_14.md`、34,358 頭・34 マス全探索で CI 下限 >100% は 0 個)。

## ただし高い目標は検証を容易にする

損益分岐からの距離が大きいほど、少ない件数で証明できる:

| 真の回収率 | 1 賭けの SD | CI 下限 >100% に必要な件数 |
|---|---|---|
| 105% | 2.8 | 12,048 件 |
| 120% | 4.0 | 1,537 件 |
| **140%** | **6.0** | **865 件** |

**140% を狙うなら封印窓の規模で十分証明できる**。
以前「800 レースでは判定できない」と述べたのは限界的エッジ (105-110%) 前提の話で、
本憲法の目標水準では当てはまらない。

## 憲法の核心 (方針 2) を実装した結果

`logit(P) = logit(P_market) + f(特徴)` を LightGBM の `init_score` で実装
(`scripts/sim/residual_learn.py`)。学習 59,524 頭 / 検証 10,094 頭 (2026-07〜09)。

| | 市場に対する情報利得 |
|---|---|
| 市場だけ (基準) | 対数損失 0.21047 / AUC 0.8372 |
| 誤差学習 lr=0.02 木200 | **+0.053** (×10⁻³) |
| 誤差学習 lr=0.02 木500 | −0.741 |
| 誤差学習 lr=0.05 木300 | −1.498 |

比較: 同手法での陽性対照は **+43,214** (×10⁻⁶ = +43.2×10⁻³)。
**急造 20 特徴では市場の誤差を検出できていない**。容量を増やすと悪化する。

構造としては正しく動いている (市場の再発見に容量を使わなくなった) が、
**方針 4 (交互作用による誤価格の発生場所の特定) が未実施**。

## 本憲法が解決する懸案

**F3 封印の開始日 (2026-10-01 予定)**:
方針 8 は「Final Lockbox は開発完了まで一切見ない」「同じテストで条件変更して
140% を作ることを禁止」と定める。**現時点で試す価値のある候補が無い**
(本番モデルの市場に対する重みは −0.130、`MODEL_VS_MARKET_2026_09_15.md`)。
候補が無いまま封印を開始すると、一度きりの Lockbox を既知の答えの確認に費やす。

→ **封印開始を延期し、「開発段階で一定水準を超えた候補が出た日」に開始する**
   のが本憲法と整合する。開始基準は事前に数値で固定すること。
   **9 月 30 日までに `config.SEALED_FROM` を変更しないと自動的に封印が始まる**。

## 実施計画

### Phase 0 — 基盤 (方針 2/3/6/7/8/11)

1. **データ分割を 4 分割に再設計**: 学習 / Validation / Strategy Development /
   Final Lockbox。現行の封印 (`config.SEALED_*`) は Final Lockbox に対応させる。
2. **市場オフセット学習を本流にする**: `init_score = logit(P_market)`。
   `P_fundamental` (オッズ不使用) は方針 6 のため別途保持し `Edge = P_fund/P_market` を出す。
3. **評価バッテリーを 1 本化**: LogLoss / Brier / Calibration / 市場に対する情報利得 /
   EV / 実回収率 / 最大ドローダウン / 購入件数 / 上位払戻 1・5・10 件除外後の回収率 /
   Bootstrap 信頼区間 / 連敗数。**的中率と AUC は診断用に留め、合否に使わない**。
4. **4 段階を分離**: ①確率 → ②期待値 → ③購入/見送り → ④資金配分。

### Phase 1 — 市場の弱点の地図を作る (方針 4/14)

Strategy Development 期間のみを使い、**市場の Calibration 誤差**を条件別に測る。
単独条件ではなく交互作用を重点探索する。**探索は多重比較補正込みで評価し、
「見つけた」ものは必ず Validation で確認する**。

### Phase 2 — 候補の検証 (方針 9/10/12/15)

候補が出たら事前登録 → Validation で確認 → 合格条件を満たすか判定。
**Final Lockbox には触れない**。

### Phase 3 — Lockbox (方針 8)

Validation を通過した候補が出た時点で初めて封印を開始し、規定件数到達後に 1 回だけ判定。

## 過去方針との差分 (何を捨てるか)

  **140% の証明**に引き上げられた。

  過去に棄却したのは「単勝プールから Harville で導出する」方法であって、
  独立にモデル化する道は未検証。
